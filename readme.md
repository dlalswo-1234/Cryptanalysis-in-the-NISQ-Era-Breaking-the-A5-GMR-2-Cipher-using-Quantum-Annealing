# Cryptanalysis in the NISQ Era: Breaking the A5-GMR-2 Cipher using Quantum Annealing

**USENIX Security '26 Cycle 1 Submission #1096**

## 📋 Project Overview

This repository contains the implementation code and experimental results for quantum annealing-based A5-GMR-2 cipher attack research. The project demonstrates cryptographic attacks using both classical computing methods and quantum computing (D-Wave) approaches.

## 🛠️ Programming Languages

- **C++**: Core computational algorithms for adjacency matrix generation
- **Python**: Data analysis, visualization, and result processing

## 📁 Repository Structure

### `Results_on_Classical/`

Contains results from classical computing approaches for **Section 3.3 "On the Reported Number of Key Candidates"**. This section analyzes key candidate distributions using traditional computational methods.

#### Data Organization
- **`Data_1/`, `Data_2/`, `Data_3/`**: Results organized by different known keystream lengths
  - Each contains test cases `test_00001/` through `test_10000/`
  - Individual test folders contain `.txt` files named after C++ random seed values
- **`Linux/`, `Windows/`**: C++ code for generating graph adjacency matrices from keystreams created with random seeds (for Linux, for Windows)
- **`Windows_check/`, `Linux_check/`**: C++ code for counting key candidates for all keystream lengths (for Windows, for Linux)

#### Core Scripts
- **`solve_parallel.py`**: Python script for data processing and result analysis

#### Results and Visualizations
- **`solutions_distribution_KS1`**: Key candidate distribution for keystream length 1
- **`solutions_distribution_KS2`**: Key candidate distribution for keystream length 2  
- **`solutions_distribution_KS3`**: Key candidate distribution for keystream length 3

#### Processed Data
- **`sol_count_dict_1.pkl`**: Solution count dictionary for known keystream length 1
  - Format: `dict[test_num] = num_of_key_candidates`
- **`sol_count_dict_2.pkl`**: Solution count dictionary for known keystream length 2
  - Format: `dict[test_num] = num_of_key_candidates`
- **`sol_count_dict_3.pkl`**: Solution count dictionary for known keystream length 3
  - Format: `dict[test_num] = num_of_key_candidates`

#### Combined Analysis
- **`gen_figure.ipynb`**: Jupyter notebook for generating figures and visualization plots

---

### `Results_on_DWave/`

Contains results from D-Wave quantum computing experiments using quantum annealing approaches.

#### Experiment Directories
- **`_Experiment_Result_KS1/`**: Quantum annealing results for known keystream length 1
  - `repeated_execution_results/`: Batch execution results (auto-generated by QA-aided-A5)
  - `run_data/`: Individual test run data (auto-generated by QA-aided-A5)
- **`_Experiment_Result_KS2/`**: Quantum annealing results for known keystream length 2
  - `repeated_execution_results/`: Batch execution results (auto-generated by QA-aided-A5)
  - `run_data/`: Individual test run data (auto-generated by QA-aided-A5)
- **`_Experiment_Result_KS3/`**: Quantum annealing results for known keystream length 3
  - `repeated_execution_results/`: Batch execution results (auto-generated by QA-aided-A5)
  - `run_data/`: Individual test run data (auto-generated by QA-aided-A5)
- **`Linux/`, `Windows/`**: Platform-specific code for generating graph adjacency matrices from keystreams created with random seeds

#### Analysis Tools
- **`gen_figure.ipynb`**: Figure generation for quantum results
- **`QA-aided-A5-GMR-2-Attack.ipynb`**: Quantum annealing aided A5/GMR-2 attack implementation
  - Converts cryptographic problems to QUBO (Quadratic Unconstrained Binary Optimization) format
  - Executes repeated attacks using D-Wave quantum annealer
  - Requires D-Wave Ocean SDK and license

## 🔑 Key Parameters

- **KS1, KS2, KS3**: Different known keystream lengths used in the analysis
- **Test Cases**: 10,000 test cases per keystream length
- Results demonstrate how the number of key candidates varies with keystream length

## 🚀 Usage

1. **Classical Analysis**: Run `solve_parallel.py` for keystream lengths ≥ 2
2. **Quantum Analysis**: Execute `QA-aided-A5-GMR-2-Attack.ipynb` for quantum annealing experiments
3. **Visualization**: Use `gen_figure.ipynb` notebooks to generate result plots

## 📊 Results Summary

The project analyzes the relationship between known keystream length and the resulting number of key candidates, comparing classical C++ implementations and quantum approaches to demonstrate:

- Computational differences between classical algorithms and quantum annealing
- Performance efficiency comparisons
- Success rates and timing analysis for both approaches
- Statistical distributions of key candidates across different keystream lengths
